SUPERAGENT  /  RESEARCH REPORT
1 调查研究
本专题围绕两个问题调研：主 Agent 如何识别意图并路由到正确 Agent；数字员工访问敏感数据、调用工具和执行外发操作时，如何保证权限不被模型绕过。
1.1 主 Agent 意图识别方案
纯规则在明确指令上稳定，但对同义表达容易漏判；纯 LLM 能补充语义，但 Prompt 不能构成安全边界。因此项目用 Intent Catalog 统一意图，规则识别显式动作、实体和否定，可选语义模型补充隐含意图，融合后由 TaskProfile 校验。关键对象缺失时生成具体澄清问题。
1.2 Agent 路由方案
项目选择中心化主 Agent。主 Agent 先取得 authorized_agent_ids，未授权 Agent 不进入候选打分；再根据 AgentCard 中的 intents、capabilities、supported_actions、accepted_data_scopes 和 risk_ceiling 进行过滤和排序。这样，权限是硬约束，而不是路由分数中的一个可被其他高分抵消的权重。

1.3 权限治理方案
RBAC 能表达稳定岗位，但同一 HR 经理查询基本信息与外发工资证明不应得到相同结果。S-ABAC 进一步考虑资源敏感级别、业务目的、数据范围、环境和动作风险。原型内嵌 PolicyEngine，并按 PIP、PDP、PEP、PAP 分层，后续可替换为 OPA、Cedar 或企业权限平台。

2 研究成果
2.1 主 Agent 意图识别与路由成果
项目形成了统一入口 make_routing_decision，执行顺序为“任务画像 → AgentCard → 权限候选 → 路由决策”。TaskProfile 显式保存主意图、子意图、实体、动作、数据范围、风险、不可逆标志、缺失字段、置信度和任务依赖；RoutingDecision 保存选中 Agent、Top-K 候选、分项得分、排除原因、reason_codes 和 trace_id。
图 2-1  主 Agent 意图识别与决策流程
2.2 权限治理成果
当前演示配置包含 6 个用户画像、18 个 Agent 安全属性、42 个资源安全属性和 3 条显式策略。PolicyEngine 根据 Subject、Object、Scenario、Action 返回 ALLOW、DENY 或 REVIEW_REQUIRED；未知用户、未注册资源和关键属性异常默认拒绝。
图 2-2  已实现的四道权限治理闸门
路由前过滤：无权 Agent 不进入候选集合。
Agent 派发前：重新校验目标 Agent、任务动作、数据域和风险。
工具调用前：每次 MCP/Tool 调用重新鉴权，Agent 可用不代表其全部工具可用。
结果返回前：Artifact Guard 校验所有者、敏感级别、数据范围和校验和。
2.3 评测集与量化结果
意图评测集包含 33 条用例，覆盖单意图、跨域复合、隐式依赖、同义表达、条件任务、缺失字段、否定、咨询误触发和关键词边界。权限评测覆盖合法访问、越权工资查询、未知工具、岗位不匹配、邮件/会议审批、Artifact 跨用户读取、审批并发消费和副作用恢复。
