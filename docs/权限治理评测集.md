# SuperAgent 权限治理评测集

更新日期：2026-08-01

这份评测集用于验证 S-ABAC、TaskGraph 调度、可信 Artifact、人工审批、人工核对和治理记录清理。它只验证权限治理，不包含任何“模型不可用时使用默认结果”的降级。

机器可读用例位于：`tests/evaluations/permission_governance_eval.json`。

## 一、启动治理模式

在项目根目录执行：

```powershell
.\start-superagent-governance.ps1
```

确认以下端口已启动：8000、8001、8010、8011、8012。然后访问：

```text
http://127.0.0.1:8001
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8001/api/health/ready
```

## 二、一键执行确定性 API 评测

保持服务运行，另开 PowerShell：

```powershell
.\.venv\Scripts\python.exe tests\evaluate_permission_governance.py
```

预期结果：12/12 passed。

只运行某一条：

```powershell
.\.venv\Scripts\python.exe tests\evaluate_permission_governance.py --case PG-API-002
```

三种决策含义：

- `ALLOW`：允许直接执行。
- `REVIEW_REQUIRED`：静态资格满足，但必须人工审批；审批前不得产生副作用。
- `DENY`：禁止执行，不能通过审批将其改成允许。

Security 页面应把工具分成“Directly accessible / Approval required / Blocked”三类，不能把需审批资源显示成直接可用。

## 四、端到端工作流评测

### PG-WF-001 管理员完整闭环

用户选择 `admin`，输入：

```text
查询员工李娜的基本信息和薪资数据，生成收入证明，然后发给王经理
```

预期：

- 任务最终 `SUCCEEDED`。
- 操作模式依次为 read、write、send。
- 所有输出 Schema 合法。
- 管理员演示豁免下不产生待审批记录。
- 不产生人工核对记录。

### PG-WF-002 HR 工资查询审批

用户选择 `hr_manager`，输入：

```text
查询员工李娜的工资信息
```

预期：工资工具执行前暂停，Security 的人工审批队列出现一条 pending 记录。审批前不能调用工资工具产生结果。

在 Security 页面切换为 `admin` 后批准，再恢复原任务。预期审批状态变成 `consumed`，同一审批不能消费第二次。

队列查询：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8001/api/security/approvals?requester_id=admin&status=pending'
```

### PG-WF-003 工程师越权查询工资

用户选择 `engineer`，输入：

```text
查询员工李娜的工资信息
```

预期：DENY 或找不到授权 Agent；不生成工资结果，不生成文档，不发送邮件，也不能通过审批把 DENY 变成 ALLOW。

### PG-WF-004 外发邮件审批

用户选择 `communication_officer`，输入：

```text
给外部联系人发送一封项目通知邮件
```

预期：真正发送前进入 `REVIEW_REQUIRED`。审批前 `assets/email_log.json` 不应新增该邮件记录。

## 五、Artifact 数据权限评测

先验证远程 Agent 内部工具不能绕过主服务治理：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -o "addopts=" tests/test_remote_tool_gate.py tests/test_remote_invocation_contract.py
```

必须验证：

- 远程资源注册表中的每一个工具都存在 S-ABAC 安全属性。
- 员工基本信息步骤只授权人员工具，不能顺带获得薪资工具权限。
- 薪资步骤在远程 Agent 真正执行前触发审批，审批绑定员工、操作模式和任务场景。
- 远程 Agent 选择了主服务授权清单以外的工具时直接拒绝，不能访问 8011 工具服务。
- 差旅和日程根据 TaskGraph 的 read/write 模式分别映射查询与写入资源。

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -o "addopts=" tests/test_artifact_guard.py tests/test_artifact_adapter.py tests/test_scheduler.py
```

必须验证：

- 跨用户读取工资 Artifact 被拒绝。
- Planner 自报 `allowed_reader_ids` 不生效。
- 只有标记为 `trusted_server` 的读者名单可以授权跨用户读取。
- 用户无权调度的消费 Agent 不能读取其 Artifact。
- Schema 校验失败的 Artifact 不能向下游传递。
- 审计日志只记录元数据，不能记录工资正文等 payload。

## 六、审批与人工核对评测

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -o "addopts=" tests/test_governance_approval.py tests/test_governance_web_api.py tests/test_s_abac.py
```

必须验证：

- 审批指纹绑定用户角色、grant、资源敏感度、场景和完整参数。
- 上述任一内容改变后，旧审批不能复用。
- 16 个并发恢复请求只能成功消费一次审批。
- Guest、HR 和未知用户不能批准、拒绝或处置人工核对记录。
- 人工核对只有确认“未执行”后才可安全重试。
- 确认外部成功必须填写 external_operation_id。
- 不确定副作用不会自动重试。

## 七、治理记录清理评测

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -o "addopts=" tests/test_governance_web_api.py -k "cleanup or deleting"
```

预期：

- 普通用户不能删除其他用户的任务证据。
- 任务所有者可以删除自己的运行记录。
- admin 可以执行治理清理。
- 删除任务会清理 task log、checkpoint、receipt、Artifact、治理时间线、审批和人工核对记录。
- 已生成的业务 Word 文档和外部系统结果保留。

## 八、完整回归

```powershell
.\.venv\Scripts\python.exe -m pytest -q -o "addopts="
```

验收标准：

- 0 failed、0 errors。
- Security 待审批、待核对队列中没有测试遗留孤儿记录。
- 权限拒绝必须能在任务治理时间线中找到 subject、resource、decision 和 reason。
- 任何 DENY 都不能因人工审批被提升为 ALLOW。
- 模型错误仍按错误处理，不允许使用默认任务结果兜底。
